## 3. mediamtx 与网络链路

```bash
# 在跑吗？（有输出=在听）
netstat -ano | grep -E ":8554.*LISTEN"

# 启动（若没在跑）
cd /c/Users/<user>/Downloads/mediamtx_rtsp && ./mediamtx.exe &

# 板子在推流吗？（有 ESTABLISHED 来自 <板IP>=在推）
netstat -ano | grep -E ":8554.*ESTABLISHED" | head -3
```

- PC 防火墙已放行 mediamtx.exe（TCP 8554/8889/8888/1935 + UDP 8000/8001/8189）。新机器部署要重放行。
- mediamtx 长跑状态可疑（404/流卡）→ 干净重启 mediamtx。
- USB 通路需 `adb -s <serial> reverse tcp:8554 tcp:8554`；**adb server 重启会清空所有 reverse**——hdmiin 404 先 `adb reverse --list`。
- WSL 里的 127.0.0.1 ≠ Windows 的 127.0.0.1（NAT 隔离）：RTSP/mediamtx 相关探测要么用 Windows 工具（WinGet ffmpeg），要么用板/PC 的局域网 IP。**WSL 只用于它的 python3（cv2+onnxruntime）拉 `rtsp://<PCIP>:8554/hdmiin` 这类 LAN 地址。**

## 4. PC ONNX 验证（离线模型侧）

### 4.1 Studio 内置"本地 ONNX 验证"（2026-10-17 新增）

界面是**双页结构**（顶部导航栏切换）：**◉ LIVE / 实时预览**（工程+信号源+日志+预览大屏）和 **⚡ ONNX LAB / 本地推理**（模型/图片路径 + **置信度/NMS IoU 数字框** + ⚡本地推理按钮 + **📊 模型分析** + **🔍 Netron** + 独立结果大屏）。推理后大屏画检测框，底部细节条显示耗时分解（载入/预处理/推理/后处理/合计）、所用阈值（conf/iou）与检出框数，右下角显示 `ONNX N 框`。可调参数：conf 0.05~0.95 步 0.05（默认 0.25）、IoU 0.10~0.90 步 0.05（默认 0.45）；命令行等价 `onnx_infer.py <img> <model> [conf] [iou]`。输入尺寸/预处理/后端固定（模型训练时已定）。

**📊 模型分析**（tools/onnx_analyze.py，QProcess 同模式）：弹窗显示 文件大小/参数量/MACs+GFLOPs（onnx shape inference 推 Conv/Gemm/MatMul）/输入输出 schema/算子直方图/**逐层真实耗时 TOP15**（onnxruntime enable_profiling，N 次取均值，已过滤 ORT 内部 Reorder 噪声）。基线：yolov8n → 12.6M 参数、4.34 GMACs（=8.7 GFLOPs，与官方一致）、CPU 50~80ms/次。**首次分析较慢**（shape 推断），属正常。

**🔍 Netron**（WSL 已 `pip install netron` 9.3.2）：按钮 → 杀旧实例（pkill `[n]etron --host` 防自匹配）→ `netron --host 127.0.0.1 --port 8086 <模型>` → 轮询 HTTP 200 → 自动打开 Windows 浏览器 `http://127.0.0.1:8086` 看模型图。Netron 只看结构，性能看 📊。注意：netron 装在 `~/.local/bin`，**必须 login shell（bash -lc）才有 PATH**。

实现：`core/onnxrunner.cpp` QProcess 调 `wsl.exe -d Ubuntu-22.04 -- python3 tools/onnx_infer.py <img> <model> [conf]`，stdout 最后一个非空行为 JSON。**依赖开发机 WSL**（cv2+onnxruntime 自带零安装）；交付纯 C++ 版时换 ONNX Runtime C API（升级路径，UI/数据结构已就绪，只换 OnnxRunner 内部实现）。

解码支持（tools/onnx_infer.py）：
- 标准展平导出 `(N,ch)/(1,N,ch)/(ch,N)`（obj+cls 与 v8 无 obj 两种）
- 单输出 4D 图内已解码 `(1,4+K,H,W)`
- **裸头 DFL 金字塔 `(1,64+K,H,W)`**（自训 convert 形态；softmax 16 bins + dist2bbox，cls 需 sigmoid）
- **rknn_model_zoo 分组金字塔**：每层 3 输出 `[(1,64,H,W),(1,K,H,W),(1,1,H,W)]`（COCO K=80）——DFL 需 softmax，**cls/obj 图内已激活，直接当概率用**（黑图输入下恰为 0 可证；再叠 sigmoid 会把 0.87 压到 ~0.5 并出上千假框）
- 其余（pose 双头等）报"非标准输出头"→ 归模型家族插件

路径：Qt 侧 `toWslPath` 同时支持盘符（`C:\...`→`/mnt/c/...`）与 **UNC**（`\\wsl.localhost\<发行版>\home\...`→`/home/...`，文件对话框从 WSL 仓库选文件即此形态）；脚本侧 norm_path 同样容忍。

### 4.2.1 📡 板端 NPU 性能（B 路径，2026-10-17 新增）

RKNN LAB 的 **📡 板端性能** 按钮：把"存 .rknn"的模型 + 测试图推到板上 perf 工程，**双配置测量**——full（src→letterbox→infer→out）与 base（无 infer）各跑 5 轮×10 帧，**差值=NPU 纯推理增量**（扣除 imwrite 等公共开销）。细节条显示"推理增量 X ms/帧 · full e2e · base"。前提：板在线 + 已跑过带"存 .rknn"的模拟推理。**工程流水线严禁加 post 段**（yolov5_det 解码遇到非预期输出头会段错误——billiards 12 输出实测）。基线：billiards yolo11s fp16 @3576 = 推理增量 ~103ms/帧（int8 量化可再快 2-3 倍）。

**toolkit2 eval_perf / accuracy_analysis 已解锁（10-18 网络路径）**：有网络的板不需要 usbipd——`adb -s <serial> tcpip 5555` → WSL 原版 Linux adb（toolkit2 私有那份，**勿用 Windows shim**）`adb connect <板IP>:5555` → `tools/rknn_perf.py <onnx> <板IP>:5555 [meanstd]`。实测 billiards yolo11s fp16 @3576：**Total 54.8~56.5ms/帧 = 17.7~18.2 FPS（真 NPU）**，板上 API 2.3.2 / server 2.3.2 / rknnrt 2.3.0 对齐；accuracy_analysis 同链路通过（逐层余弦 0.9999+，error_analysis.txt 落盘）。姿势：板上须运行 2.3.2 配对 rknn_server（vendor 版复活会协议失配 → eval 静默失败）；device_id 传 `IP:5555`。**仅 USB 的板才需 usbipd-win**（Windows adb.exe 不支持 localabstract 转发，未做）。

## 6. 故障排查表（症状 → 根因 → 修法）

| 症状 | 根因 | 修法 |
|---|---|---|
| Qt MJPEG"已连接"但无帧，日志刷"已接收 X KB" | 部署缺 `imageformats\qjpeg.dll` → loadFromData 静默失败 | 按 §1.3 清单补；排障定式：**Qt 无画面先查部署目录** |
| QMediaPlayer 零状态回调/无"加载中"日志 | 部署缺 FFmpeg 5 DLL → ffmpegmediaplugin 加载失败 | 补 avcodec-61 等 5 个（§1.3） |
| RTSP 状态走到"缓冲中"后永不出帧 | 推流端 RTP 时间戳坏（步进≠真实帧间隔）。ffmpeg/VLC 容忍，Qt FFmpeg 后端的时钟不容忍 | §2.4 ② 查 pts_time 步进；推流端时间戳=挂钟自打（RtspPushClient 已修，勿改回编码器回传 pts） |
| 全屏花屏 + 解码报 error while decoding MB | FU-A 载荷偏移错（应 `off+pos`，pos=1 已跳 NAL 头） | RtspPushClient.emitNal 已修，别动 |
| RTSP SETUP 400 | 推送端缺 `mode=record` 或发的是 PLAY | Transport 加 mode=record，用 RECORD |
| Java 报 RTP 包拷贝越界 (srcPos/dstPos) | 包分配漏 12B RTP 头，应 `28+len`（4B $头+12B RTP 头+载荷） | sendRtp 已修，别动 |
| gradle 卡住不动（十几分钟无输出） | WSL 侧 gradle 发行包只有 `.part`，在慢慢重下 | 用 §2.2 的 Windows bat 构建；或按 §2.2 ⚠️ 补 WSL 缓存 |
| gradlew 报 JAVA_HOME invalid / not set | Windows 用 scoop JDK；WSL 要 login shell 才有 java | bat 里 `set JAVA_HOME=C:\Users\<user>\scoop\apps\temurin21-jdk\current`；WSL 用 `bash -lc` |
| cmd.exe 命令没执行、只弹了横幅 | Git Bash 的 `/c` 被 MSYS 路径改写吃掉 | `MSYS_NO_PATHCONV=1 cmd.exe /c "..."`（禁转换时 `/c`/`//c` 只能用前者） |
| rtsp://…/hdmiin 404 或无 publishing | adb reverse 被清（USB 通路）/ App 没在推 / mediamtx 刚重启 | `adb reverse --list` → 重注册 `tcp:8554`；看 §3 ESTABLISHED；重启 mediamtx |
| ffprobe/Qt 连不上 127.0.0.1:8554（但命令在 WSL 跑） | WSL 的 localhost ≠ Windows localhost | 用 Windows 工具，或改 LAN IP `rtsp://<PCIP>:8554/hdmiin` |
| 板 URL 连不上（之前好的） | 板 WiFi IP 漂移 | `adb -s <serial> shell ip -4 addr show wlan0` 拿新 IP，替换 URL |
| 拉到的"MJPEG"是 HTML、连接循环断开 | 填了 mediamtx 网页页面 URL（:8889/:8888 是给人看的页面） | MJPEG 填 `http://<板IP>:8080/stream`；RTSP 填 `rtsp://...` |
| 板上有流但画面内容是系统 UI 旋转 90° | 抓到了下拉快捷设置遮罩（板子屏幕停在 shade） | 拉回 rvs-cam 前台 / 正常桌面后重试 |
| 板子反复 stop/start 后 connected 但无帧 | HAL/采集状态卡死 | `adb reboot` 复位最省时间；重启后 am start App + 重注册 reverse |
| Qt 改了代码但行为没变 | 没重编/没拷 exe 到部署目录 | §1.2 + §1.3 两步都要做 |

## 7. 记住的三条铁律

1. **Qt 无画面先查部署目录**（imageformats\qjpeg.dll、FFmpeg 5 DLL、multimedia\），不要先怀疑代码——用 `--screenshot` 截图回归快速二分。
2. **App 构建永远走 Windows**（build_qb.bat）；WSL gradle 只在缓存补齐后可用。
3. **验证靠自动截图 + ffprobe 数字**（pts_time 步进、http 200、ESTABLISHED），不靠肉眼等窗口。
