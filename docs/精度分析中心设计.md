# 精度分析中心设计（Accuracy Lab）

> 状态：设计稿 v1（2026-10-21），待评审。
> 背景：ONNX LAB 与 RKNN LAB 各自为战——①没有"转换过程精度丢失"的对比能力，②toolkit2 的调试功能（四级精度排查、混合量化、LOG_LEVEL 逐层 dump）未被挖掘。本文把两者统一为"精度分析中心"。
> 依据：rknn-toolkit2 官方《User Guide v2.3.2》第 6 章（量化说明/混合量化）、第 7 章（精度排查）、rknn_model_zoo yolov8.py 双容器验证模式、本项目 rknn_acc.py 真板验证。

---

## 1. 官方方法论（文档研究结论）

### 1.1 四级精度排查漏斗（User Guide 第 7 章）

官方的精度排查是**漏斗式逐级定位**，每级回答一个问题：

| 级 | 对象 | 回答的问题 | 工具 |
|---|---|---|---|
| ① | ONNX / pt（float32） | 金标准是什么 | onnxruntime / pytorch |
| ② | RKNN **FP16** 模拟（do_quantization=False） | 转换为 FP16 有没有丢？ | init_runtime(target=None) |
| ③ | RKNN **int8** 模拟（do_quantization=True + 校准集） | **量化**伤了多少？伤在哪层？ | 同上 + accuracy_analysis |
| ④ | 板上 Runtime | 板端实现/部署代码有没有再丢？ | 连板推理 / RKNN_LOG_LEVEL=5 |

**官方判读规则**：
- 前一级正确是后一级正确的前提——逐级排查，不许跳
- ③ 的 `sim_single_cos` 偏低 → 量化敏感层 → **混合量化**（§6.3）治疗
- ④ 的 `runtime_error.single_sim` 偏低 → **板端 Runtime bug**（反馈瑞芯微）；否则查 C API 配置/前后处理
- 板上设 `RKNN_LOG_LEVEL=5` → 普通推理也逐层 dump numpy 到 `/data/dumps`（Android）——检查 InputOperator/OutputOperator 即验证输入输出配置

### 1.2 诊断→治疗闭环（§6.3 混合量化）

```
accuracy_analysis（找病灶：哪些层 sim_single_cos 低）
→ hybrid_quantization_step1（生成 {model}.quantization.cfg）
→ 按诊断把敏感层改为 float16（custom_quantize_layers: 层名: float16）
→ hybrid_quantization_step2（重构建）
→ 复测 accuracy_analysis 验证回升
```

另有**自动混合量化**（§6.3.3，可自动决定敏感层）；量化算法可切换（normal/mmse/kl_divergence，§6.2.2）；量化感知训练 QAT 是最后手段（§6.4）。

### 1.3 官方模型验证模式（rknn_model_zoo yolov8.py）

`setup_model()` 按扩展名选容器：`.rknn → RKNN_model_container`，`.onnx → ONNX_model_container`——**同一脚本、同一前后处理、同一张图**，喂哪种模型都能推理。两次运行的输出做差 = 转换过程的精度丢失。这是 rknn_model_zoo 全部 example 的统一验证模式。

## 2. 现状盘点（已有哪些积木）

| 已有 | 缺的 |
|---|---|
| ① ONNX 推理（ONNX LAB，onnxruntime） | ①↔② 输出对比（框级 IoU 匹配 + 余弦） |
| ② RKNN FP16 模拟（RKNN LAB，rknn_sim.py） | ②↔③ 量化前后对比（同一校准图） |
| ③ RKNN int8 构建（rknn_acc.py 量化构建已验证） | ③→④ 板端实现一致性检查（LOG_LEVEL=5 dump 对比） |
| ④ 板上部署运行（Deployer + rknn_acc 连板已验证） | 四级结果的可视化汇总 |
| accuracy_analysis 诊断（rknn_acc.py，94 层余弦） | 混合量化向导（诊断→cfg→治疗→复测） |

**结论：四个推理引擎全部已验证，缺的是"对比层"和"向导层"。**

## 3. 设计：精度分析中心

### 3.1 统一对比台（P1，核心）

一个"精度对比"动作跑四级，输出三份报告：

```
输入: 模型.onnx + 校准图（1~N 张）+ 板（可选，不在线则跳过④）
  ① onnxruntime 推理 → 检测框/输出
  ② rknn fp16 模拟    → 检测框/输出        （rknn_sim 现有管线，do_quant=False）
  ③ rknn int8 模拟    → 检测框/输出        （do_quant=True + dataset）
  ④ 板上推理          → 检测框/输出        （板在线时）

报告 A 端到端框匹配: ①为基准，②③④各与它做 IoU 匹配（≥0.5 同框），
                     每框列出 conf 差/坐标差 → 转换丢精度=某框 conf 掉多少
报告 B 端到端张量:   三方最终输出的余弦
报告 C 逐层:         ③ 的 accuracy_analysis（现有 rknn_acc.py）
```

### 3.2 混合量化向导（P2）

```
读取 P1 报告 C → 列出 sim_single_cos 最低的 N 层（勾选）
→ 自动生成 .quantization.cfg（custom_quantize_layers: 层名: float16）
→ hybrid_quantization_step2 重构建
→ 自动复测 accuracy_analysis → 前后对比表（层 X: 0.97→0.999）
```

### 3.3 可视化（P3）

- 漏斗总览：四级余弦曲线（①基准线 + ②③④ 逐级衰减）+ 各级损失贡献条
- 检测框叠加对比图：①绿框 ③红框 ④黄框 画在同一图上，人眼直接看漂移
- 逐层余弦曲线图（替代纯文本表）

### 3.4 调试工具箱（随 P1/P2 附带）

- `RKNN_LOG_LEVEL=5` 开关：板上普通推理也逐层 dump（拉回本地对比输入输出配置）
- 量化算法切换：normal / mmse / kl_divergence 对比
- onnx_edit（toolkit2 §5.13）：模型结构调整

## 5. 与现有页面的关系

- ONNX LAB：不动（纯 PC 基线 + 模型分析 + 逐层体检）
- RKNN LAB：不动（模拟/转换/板端性能/量化精度）——🎯按钮产生的 accuracy_analysis 报告成为 P1 报告 C 的输入
- 新增能力挂在 RKNN LAB（"精度对比"按钮）+ 报告弹窗（P3 升级为可视化页签）
- 定位：**两个 LAB 的"对比中枢"**——①的图喂给②③④，四级结果回到同一张报告里
