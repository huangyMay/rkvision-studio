# 一帧的旅程 —— RKVision Studio 推理全链路导学（真实数值版）

> 这篇是给"想在 Studio 里真正学会推理"的你写的。方法只有一条：**跟着一帧真实数据走完全程，每一步都看真实数字**。
> 所有数字都来自本仓库的 helmet_gold 工程（金张量 + 最近一次板上/主机运行的真实输出），不是编的例子。
> 读法建议：先通读一遍叙事，再对照第 8 节自己动手复现一遍——能复现才算学会。

## 0. 全景：一帧要经过的十个驿站

```
test.jpg (1024×800 BGR)
  → ① letterbox (缩放+白边, 640×640)
  → ② BGR→RGB, NHWC→NCHW, uint8
  → ③ NPU 推理 (一次 infer, 出 3 张 int8 张量)
  → ④ 反量化 (int8 → 0~1)
  → ⑤ 解码 (3 尺度 × 3 anchor, xywh 还原)
  → ⑥ 阈值 + NMS (17 框留下)
  → ⑦ 坐标还原回原图
  → ⑧ judge 判决 (过滤 + 规则 → OK/NG)
  → ⑨ archive 存档 (NG 才落盘)
  → ⑩ image_out 画框出图 (+verdict 徽标)
```

---

## 1. 原料：一帧 1024×800 的图

`projects/helmet_gold/assets/test_images/test.jpg`：1024×800，三通道 BGR。
模型在训练时吃到的就是这种"原尺寸任意"的图，所以第一件事是把它变成模型认识的形状。

## 2. letterbox：等比缩放 + 白边

- scale = 640 / 1024 = **0.625**（取 min(scale_w, scale_h)，保证整图塞进去）
- 缩放后：1024×800 → **640×500**
- 高度差 640−500 = 140 → **上下各补 70 像素白边（值 255）** → 640×640

> **学习点：白边为什么是 255？** 常见教程用 114（灰色）。但 helmet 金标准的工程用的 255（纯白）——
> 训练时怎么 pad，推理就得怎么 pad，**预处理必须和训练对齐**，这是逐位复刻踩出来的第一个坑。

## 3. 送进 NPU 前：BGR→RGB、NHWC uint8

OpenCV 读进来是 BGR、HWC（高×宽×通道）；模型要 RGB、NCHW（通道在前）、uint8。
**注意：归一化(/255)不在 CPU 做**——板上由 runtime 的 mean/std 配置在推理内部完成，CPU 侧只搬运字节。

## 4. NPU 的产出：三张 int8 张量

一次 infer，拿回三张 int8 张量（对应 stride 8/16/32 三个检测头）：

| 张量 | 字节数 | 形状（按平面理解） | 含义 |
|---|---|---|---|
| out0 | 134400 | 21 × 80 × 80 | stride 8，管小目标 |
| out1 | 33600 | 21 × 40 × 40 | stride 16，管中目标 |
| out2 | 8400 | 21 × 20 × 20 | stride 32，管大目标 |

**21 = 3 个 anchor × 7**（7 = 4 个框参数 + 1 个 objectness + 2 个类别 head/helmet）。
你可能在别处见过 255——那是 COCO 80 类的（3×(5+80)）。**通道数随类别数变**，这就是"换个模型后处理要跟着换"的根源。

真实 int8 分布：三张张量的值域都是 [-128, 127]（满幅），这是 int8 量化的常态。

## 5. 反量化：把 int8 变回 0~1

attrs_probe 从板上提取的量化参数（`attrs.json`）：三个输出都是 **zp=−128, scale=1/255**。

```
反量化值 = (int8 − zp) × scale = (int8 + 128) / 255
```

- int8 = −128 → 0.0；int8 = 127 → 1.004
- **zp=−128 的含义**：int8 的"零点"被钉在最小值上，让 [0,1] 区间正好铺满 int8 全量程——sigmoid/概率类输出常用这种配置。

## 6. 放大镜：那颗 conf=0.9333 的头盔是怎么解码出来的

最近一次运行的结果 JSON 里，最高分检出是 `helmet 0.9333 @(369,188,438,273)`。
它在 int8 张量里的"老家"被我们反查出来了：**out1（stride 16），anchor(59,119)，网格 (x=16, y=13)，第 14~20 号平面**。

这 7 个字节的真身：

| 平面 | 角色 | int8 | 反量化后 |
|---|---|---|---|
| 14 | box_x | −89 | 0.1529 |
| 15 | box_y | −7 | 0.4745 |
| 16 | box_w | −20 | 0.4235 |
| 17 | box_h | −43 | 0.3333 |
| 18 | **objectness** | 110 | **0.9333** |
| 19 | cls_head | −128 | 0.0000 |
| 20 | cls_helmet | 127 | **1.0000** |

解码四步（引擎 `postprocess_yolov5.cpp` 的公式，代入真实数字）：

```
dx = (0.1529 × 2 − 0.5 + 16) × 16 = 252.9      ← 框中心 x（网络坐标）
dy = (0.4745 × 2 − 0.5 + 13) × 16 = 212.2      ← 框中心 y
dw = (0.4235 × 2)² × 59 = 42.4                 ← 框宽（anchor 加权）
dh = (0.3333 × 2)² × 119 = 52.9                ← 框高
置信度 = objectness × 类别最大值 = 0.9333 × 1.0000 = 0.9333   ← 和输出一字不差
```

再从网络坐标还原回原图坐标：**先减 pad、再除 scale，最后 lround/int 截断**：

```
x1 = (252.9 − 42.4/2 − 0) / 0.625 ≈ 370.8     ← 引擎输出 369（差 ~2px = 取整截断）
y1 = (212.2 − 52.9/2 − 70) / 0.625 ≈ 190.0    ← 引擎输出 188
```

> **学习点三连**：
> ① `×2−0.5` 是 yolov5 的中心点参数化——让网络输出 0~1 时中心落在格子里；
> ② w/h 要**平方**再乘 anchor——让网络在"框宽≈anchor 宽"附近最好学；
> ③ 平面索引是 `(7a+c)×W² + i×W + j`——**布局猜错，数值全错**（我们第一次就猜错成 COCO 布局，反查了三版才对上）。

## 7. 阈值与 NMS

- 置信度 ≥ 0.25 的框进入候选（conf_thres 参数）
- 同类别内做贪心 NMS（IoU 阈值 0.45）：按分数排序，保留最高分， suppress 与其 IoU>0.45 的低分框
- 这一帧最终留下 **17 个框**，全部 helmet（0.25 阈值下没有 head 检出）

## 8. judge 判决：从 17 个框到 "OK"

helmet_gold 工程的 judge 规则（pipeline.json 可改）：

```
① score(class=*, thres=0.45)   ← 过滤器：17 框全部 ≥0.45，0 个被滤（judge.filtered=0）
② count(class=*, min=1, max=99) ← 判决规则：17 ∈ [1,99] 窗内 → 无违规
verdict = ANY_NG → 无违规 → "OK"
```

**NG 是怎么来的？** 把 score 阈值改 0.99 再跑：17 框全被滤 → count 数到 0，越 [1,99] 窗 → 违规
→ `verdict="NG"`，日志一行 `judge[NG] test: helmet_gold | count(*)=0`，NG 图+违规明细落 `ng_images/`。

新加的直出能力：结果图左上角有 **OK（绿）/ NG（红）徽标**，NG 日志带违规明细——不用再翻 json 猜判决原因。

## 9. 存档与出图

- **archive**：verdict=="NG" 才落盘（`ng_images/<图名>_ng.jpg + _ng.json`，keep_days 自动清理过期证据）
- **image_out**：画框 + verdict 徽标 + 结果 JSON（含 detections/verdict/judge/timing 全套）

## 11. 术语小词典

- **int8 量化**：把浮点权重/激活压成 8 位整数，NPU 才能高速算
- **zp / scale**：反量化的两个参数。真实值 = (int8 − zp) × scale。zp 是"int8 里的零点"位置
- **anchor**：预设的框宽高模板，网络只学"相对模板怎么修"
- **stride**：检测头一个格子对应原图多少像素；stride 越大管越大的目标
- **objectness**："这个格子里有没有东西"的置信度
- **NMS**：非极大值抑制——同一个物体被多个框命中时只留最好的
- **letterbox**：等比缩放+补边，不拉伸变形
- **金标准**：模型在板上对某张图的真实输入/输出张量+框基线，用于逐位回归

## 12. 自测六题（答案倒着排在本节末）

1. out0 有 134400 字节。若换成 4 类模型（其余不变），out0 多少字节？
2. int8=−20、zp=−128、scale=1/255，反量化后是多少？
3. 为什么置信度=objectness×类别分数，而不是只看 objectness？
4. letterbox 后框中心在网格 (16,13)、stride 16，网络坐标中心 x≈多少？
5. 把 conf_thres 从 0.25 提到 0.99，本帧判决为什么从 OK 变 NG？ violated 的是哪条规则？
6. 白边用 114 会怎样？（提示：和训练对齐有关）

**答案**：1. 3×(5+4)×6400=207360。2. (−20+128)/255≈0.4235。3. objectness 只说"有东西"，类别分数说"是什么/像不像"，乘起来才是"是这个类"的置信度。4. (0.1529×2−0.5+16)×16≈252.9。5. 17 框全被滤空，count(*)=0 越出 [1,99] 窗，count 规则违规。6. 推理分布偏离训练分布，精度掉——helmet 金标准用 255，必须跟 255。
