## 1. 🚀 性能剖析（实验室第 3 段）

### 1.1 它测什么

每帧成本拆三段（`perf_run.c` 板上直链 librknnrt，预热 5 帧后取 N 帧均值）：

| 段 | API | 含义 |
|---|---|---|
| **set** | `rknn_inputs_set` | 归一化税（u8→fp16 RNE 转换、布局拷贝） |
| **run** | `rknn_run` | **纯 NPU 执行**——两块板/两种精度的架构对比看这个 |
| **get** | `rknn_outputs_get` | 输出回传税（want_float=1 的 fp32 展开） |

### 1.2 用法

左列：`.rknn`（默认取「存/导入」）→ 目标板（**adb 序列/IP:端口** 走 adb，**root@IP** 走 ssh）
→ core_mask 预设（单核 / 单核 vs 三核 / 全矩阵…）→ 帧数 → 锁频开关（devfreq →
performance，**跑完自动恢复原 governor**）→ 🚀。

右侧：瀑布图（每 mask 一行，橙=set 绿=run 蓝=get，宽度∝ms）+ 结果表 + 进度日志。

### 1.3 部署链（全自动，首次之后跳过）

- 传输与 OS 正交：Debian 板也可能开 root adb（RK3588 Debian 即如此），按
  `getprop` 探测结果选构建方式
- Android：NDK 预编 `tools/bin/perf_run_android_arm64`（`build_perf_run.sh`，r27c）
- Debian：推 `perf_run.c` + 2.x `rknn_api.h` 板上 gcc 自编（glibc）
- 板上 `libroot` 下找 `librknnrt*.so` 软链成规范名，`LD_LIBRARY_PATH` 指过去

### 1.4 首批实测：RK3588 Debian（root adb 192.168.3.109，NPU 定频 1GHz）

yolov8n 640 输入，单核 = core_mask 0x1：

| 模型 | set | **run（纯 NPU）** | get | e2e | fps |
|---|---|---|---|---|---|
| int8 | 0.3 | **13.6 ms** | 1.1 | 15.0 | 66.6 |
| int8 三核(0x7) | 0.4 | **15.5 ms** | 1.5 | 17.4 | 57.3 |
| fp16 | 18.1 | **25.2 ms** | 6.1 | 49.4 | 20.2 |

**三个立即结论**：

1. **之前"3588 int8 54ms"是口径冤案**——那是 Lite2 `inference()` 一条龙
   （含 python 开销+输出回传），纯 NPU run 只有 13.6ms，税占了 40ms。
   板间架构对比必须看 run 段。
2. **三核切分反而慢 14%**（15.5 vs 13.6）——与 RK3576 双核 0x3 慢 39% 同族：
   单模型多核切分开销 > 收益，两代芯片一致。NPU 多核的正确用法是多**实例**
   各占一核，不是单模型切分。
3. **fp16 的 set 税高达 18ms**（u8→fp16 逐元素 RNE 转换），get 税 6ms（fp32 展开）——
   fp16 e2e 49ms 里近一半是 IO 税，这就是零拷贝 API 存在的意义。

## 2. 🔪 模型解剖（🧩 段按钮）

点一下弹窗展示 .rknn 容器四段布局（RKNN 头 / 节头 16B magic 0x00040004 /
任务表 N×40B / regcmd 流+权重）+ 任务数 + target + 权重占比。
依据：05-librknn编写 iotrace 板上实证（§4 文件布局）。

- 单文件：布局报告；双文件（CLI）：附字节差分（混合量化改了什么一目了然）
- `tools/rknn_dissect.py` 可独立 CLI：`python3 rknn_dissect.py a.rknn [b.rknn]`

## 3. 坑与事实（2026-10-25 实录）

1. **老版 rknn_api.h ABI 不配 2.x 库**：rknpu2 仓库自带头是 1.x
   （`RKNN_QUERY_IN_OUT_NUM`、无 `attr.w/h/c`）；且 1.x `rknn_tensor_attr` 结构体
   布局与 2.x 不同——query 会读回垃圾。必须用 `engine/third_party/rknn_api.h`
   （rvs_engine 同款 2.x 头）。输入字节数用 `attr.size`（不猜 dims 顺序）。
2. **3588 任务表 rc_offs 全 0**：05 的"任务 +28 偏移 = regcmd_offset"结论基于
   RK3576 y8p；3588 系列模型该字段全零（格式演进），提交分组估计对这类文件
   无效（脚本自动跳过并注 est_note）。
3. **随机输入即可测性能**：NPU 卷积计算量与数据内容无关，perf_run 无图片依赖。
4. **devfreq 恢复**：锁频前记录原 governor，finally 恢复；dmc(NPU DDR) 也要锁，
   不只 npu。
5. MSYS_NO_PATHCONV=1：wsl.exe 传 /home 路径必加，否则 Git Bash 把它改成 C:/…。
